# Бот розыгрышей

Telegram-бот для промоакций партнеров: [@giveaways_letsssgooo_bot](https://t.me/giveaways_letsssgooo_bot).

Выдача промокодов, ежедневные и финальный розыгрыши, получение призов и управление акцией через Telegram. Пользователи определяются по Telegram ID.

Стек: Go 1.26.5, Telegram Bot API, PostgreSQL 18.6, Flyway 13.11.1, Docker Compose.

## Механика акции

- **Промокоды.** Один код на пользователя за партнерский день; повторный запрос возвращает прежний. Подписка не требуется, исчерпание кодов не мешает регистрации в розыгрыше.
- **Регистрация.** Одна заявка на пользователя за партнерский день после проверки подписки. Повторы не создают дубликатов, последующая отписка не отменяет заявку.
- **Шансы.** Получение кода или регистрация дает один шанс за календарный день независимо от числа действий и партнеров. Максимум — 10; полная история активности сохраняется.
- **Ежедневный розыгрыш.** Автоматический выбор среди регистраций партнерского дня после закрытия приема. Расписание, призы и количество мест задаются в админке.
- **Финал.** Пять разных победителей по два билета и отдельный резерв. Вес участника равен числу активных дат акции, максимум — 10. Ежедневные победы не исключают участие.
- **Результаты.** Состав участников, победители и резерв сохраняются без повторного выбора. Уведомления отправляются после утверждения администратором.
- **Получение приза.** Явное согласие на передачу данных, ввод и подтверждение имени и фамилии. По умолчанию срок ответа — 48 часов с доставки уведомления; срок, начало отсчета и действия при недоставке настраиваются. При просрочке приз передается резервисту, исчерпание резерва требует решения организатора.

Одна установка обслуживает одну акцию с одним финалом и несколькими партнерами, в том числе в одну дату. Время — московское; окно приема включает начало и исключает конец. Выданные коды и регистрации доступны после закрытия приема.

## Команды и роли

| Команда | Действие |
| --- | --- |
| `/start` | Приветственный баннер и главное меню |
| `/menu` | Получение кода, участие, правила и накопленные шансы |
| `/help` | Справка |
| `/prizes` | Назначенные призы и подтверждение получения |
| `/cancel` | Отмена незавершенного ввода; регистрации, коды и шансы сохраняются |
| `/admin` | Управление акцией для администраторов |

**Организатор** управляет всей акцией, **администратор партнера** — назначенными партнерами. Права проверяются при выполнении действий, подтверждении изменений и отправке выгрузок.

Админка также поддерживает:

- Импорт промокодов: один код на строку, до 1000 строк, без повторного добавления существующих кодов.
- Настройку резерва, условий получения приза и текста согласия.
- Рассылки всем пользователям, аудитории партнера или выбранным Telegram ID в пределах роли. Аудитория фиксируется в черновике, отправка требует подтверждения.
- Статистику и CSV участников и победителей: до 100 000 строк и 8 МиБ, имена — только при сохраненном согласии.

Основные организаторы задаются в `ADMIN_TELEGRAM_IDS`, дополнительные роли — через админку по Telegram ID или `@username`. Добавление по нику доступно после `/start`. Команда `/admin` отображается в меню пользователей с правами доступа.

## Запуск в Docker

Требования: Docker с Compose и Make. Команды выполняются из корня проекта.

```sh
cp -n .env.example .env
chmod 600 .env
```

Параметры `.env`:

| Переменная | Значение |
| --- | --- |
| `TELEGRAM_BOT_TOKEN` | Токен бота |
| `POSTGRES_PASSWORD` | Пароль PostgreSQL |
| `DOCKER_DATABASE_URL` | URL БД с хостом `postgres`, портом `5432` и учетными данными из `POSTGRES_*` |
| `ADMIN_TELEGRAM_IDS` | Числовые Telegram ID основных организаторов через запятую |

Формат URL: `postgres://giveaways:<password>@postgres:5432/giveaways?sslmode=disable`. Специальные символы в учетных данных кодируются для URL. Для начальной настройки необходим хотя бы один организатор.

```sh
make docker-up
```

Compose запускает PostgreSQL, применяет миграции и запускает бота. Данные сохраняются в volume `postgres_data`. Значение `DOCKER_DATABASE_URL` передается контейнеру как `DATABASE_URL`; отдельный `DATABASE_URL` для Docker не требуется.

Получение событий — long polling, один экземпляр приложения на токен. Запуск требует отсутствия активного webhook.

### Настройка акции

Для проверки подписки бот должен быть администратором каналов партнеров. Через `/admin` задаются:

- Название, даты, правила и материалы акции.
- Партнеры, каналы, ссылки для подписки, партнерские дни и окна приема.
- Расписание розыгрышей, призы, резерв и промокоды.
- Текст и версия согласия, инструкции получения призов и срок ответа.

### Управление контейнерами

| Команда | Действие |
| --- | --- |
| `make docker-up` | Сборка и запуск бота с БД и миграциями |
| `make status` | Состояние контейнеров |
| `make docker-logs` | Просмотр логов бота |
| `make docker-stop` | Остановка бота |
| `make db-up` | Запуск PostgreSQL |
| `make db-migrate` | Применение миграций |
| `make db-validate` | Проверка примененных миграций |
| `make db-info` | Статус миграций |
| `make db-down` | Остановка PostgreSQL с сохранением данных |

## Локальный запуск

Требуется Go версии из [go.mod](go.mod). Запуск БД и миграций:

```sh
make db-up
make db-migrate
```

В `.env` задается `DATABASE_URL` с адресом хоста и портом `POSTGRES_PORT`, например `postgres://giveaways:<password>@127.0.0.1:5432/giveaways?sslmode=disable`. Приложение читает окружение; загрузка `.env` перед запуском:

```sh
set -a
. ./.env
set +a
make run
```

### Дополнительные настройки

| Переменная | По умолчанию | Назначение |
| --- | --- | --- |
| `POSTGRES_USER`, `POSTGRES_DB` | `giveaways` | Пользователь и имя БД в Compose |
| `POSTGRES_PORT` | `5432` | Порт PostgreSQL на `127.0.0.1` хоста |
| `LOG_LEVEL` | `INFO` | Уровень JSON-логов: `DEBUG`, `INFO`, `WARN`, `ERROR` |
| `TELEGRAM_POLL_TIMEOUT` | `30s` | Длительность long polling, целое число секунд |
| `TELEGRAM_REQUEST_TIMEOUT` | `40s` | Тайм-аут HTTP-запросов; должен превышать polling timeout |
| `SHUTDOWN_TIMEOUT` | `10s` | Время на завершение текущих операций после сигнала остановки |
| `BOT_STOP_GRACE_PERIOD` | `60s` | Ожидание остановки контейнера; должно превышать shutdown timeout |

Технические параметры читаются из окружения при запуске, настройки акции хранятся в PostgreSQL.

## Хранение и обработка

События Telegram сохраняются в БД. Бизнес-данные, состояние диалога и ответ в очереди записываются одной транзакцией. Ошибка записи откатывает операцию; ошибка доставки после commit не отменяет код и регистрацию.

Очередь повторяет отправки при временных ошибках и учитывает `429`. После перезапуска продолжаются обработка событий, доставка и пропущенные розыгрыши. При `SIGINT`/`SIGTERM` прекращается прием работы, текущие операции завершаются или отменяются по тайм-ауту, затем закрываются соединения.

## Тесты

Обычные тесты находятся рядом с кодом:

```sh
go test ./...
```

Интеграционные тесты находятся в `tests`, вспомогательный код — в `tests/utils`:

```sh
make test-integration
```

Интеграционные тесты запускаются с `-race`, настоящей PostgreSQL в Docker, миграциями, сервисами и репозиториями. Telegram API заменен локальным HTTP-сервером. Схемы изолированы, временные ресурсы удаляются после выполнения; рабочий `.env` не используется. Миграции проверяются через Flyway.

Покрыты коды, подписка и регистрация, шансы и временные границы, розыгрыши, призы и резерв, права, рассылки, выгрузки, транзакции и восстановление доставки. Два сквозных сценария проверяют получение приза победителем и резервистом с перезапуском приложения посередине формы.
