# Архитектура

Модульный монолит: один Go-модуль (`go.mod`), один исполняемый файл и одна PostgreSQL.

## Организация проекта

```text
giveaways_bot/
├── cmd/giveawaysbot/main.go       # точка входа
├── docs/
│   └── ARCHITECTURE.md            # архитектура и границы модулей
├── internal/
│   ├── app/                       # создание компонентов и связывание зависимостей
│   │   └── delivery/              # доставка отчетов и синхронизация команд
│   ├── config/                    # загрузка и проверка конфигурации
│   ├── handlers/<module>/         # команды, кнопки и диалоги Telegram
│   ├── services/                  # бизнес-сценарии и интерфейсы зависимостей
│   │   ├── users/                 # пользователи и права
│   │   ├── promotion/             # акция, партнеры, расписание и материалы
│   │   ├── participation/         # промокоды, заявки, активные дни и шансы
│   │   ├── draw/                  # розыгрыши, утверждение, резерв и получение призов
│   │   ├── notifications/         # рассылки и доставка уведомлений
│   │   └── reporting/             # статистика и выгрузки
│   ├── entity/<module>/           # предметные модели и правила
│   └── infrastructure/
│       ├── repository/<module>/   # SQL и реализации интерфейсов хранения
│       ├── clients/telegram/      # вызовы Bot API
│       │   ├── banner/            # отправка баннера и его ресурс
│       │   ├── commands/          # список и настройка команд
│       │   ├── document/          # отправка CSV-документов
│       │   ├── fetcher/           # получение обновлений
│       │   ├── sender/            # отправка сообщений
│       │   ├── subscription/      # проверка подписки
│       │   ├── usernames/         # проверка актуального username
│       │   └── internal/          # общие ошибки, проверка payload и тестовые помощники
│       ├── postgres/              # соединения и общие транзакции
│       └── workers/               # прием событий и фоновые задачи
├── migrations/                    # Flyway: V1__name.sql, V2__name.sql
├── deployments/                   # Dockerfile и Compose
├── go.mod
└── go.sum
```

`<module>` обозначает предметные модули `users`, `promotion`, `participation`, `draw`, `notifications`, `reporting` в соответствующих слоях. Техническое хранение входящих событий, диалогов и заданий также относится к `infrastructure/repository`. Модульные тесты лежат рядом с кодом.

Самостоятельные части модуля собраны в подпакеты вместе со своими тестами. Например, пользовательское меню находится в `handlers/users/menu`, формы управления акцией — в `handlers/promotion/forms`, импорт кодов — в `services/promotion/importer` и `infrastructure/repository/promotion/importer`. Репозиторий розыгрышей разделен на чтение и блокировки (`storage`), проведение (`execution`), утверждение (`approval`), запуск по расписанию (`runner`) и получение призов (`awards`).

Корневые компоненты связывают эти части и сохраняют общий интерфейс для приложения. Общие зависимости диалогов находятся в `session`. Небольшие вспомогательные файлы одного сценария, например `views.go` рядом с обработчиком, остаются в его пакете.
